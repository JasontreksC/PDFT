# PDFT — PDF 번역기 (Docker)

PDF의 **글자와 그 글자가 인쇄된 위치를 그대로 읽어 → LLM으로 번역 → 원본 쪽 위에 번역문을 얹는** 웹앱입니다. 번역할 글을 고르는 방법이 두 가지입니다 (작업 공간 위쪽의 **번역 방식**):

| | **기본 번역** (기본값) | **고급 번역** |
|---|---|---|
| 글상자를 정하는 것 | PDF 텍스트 층의 줄을 조판 규칙으로 묶고, **Docling이 찾은 레이아웃 구역을 힌트**로 씀 | **쪽 스크린샷을 비전 LLM**이 보고 번역할 글만 골라 줌 → 그 원문을 텍스트 층과 대조해 위치를 찾음 |
| 모델로 보내는 것 | 글상자의 **글만** (텍스트 모델이면 됨) | **쪽 스크린샷** + 지침 (이미지 입력 모델 필요, 입력 토큰 많음) |
| 수식·번호 | 문단 안에 섞인 수식도 함께 보냄 (모델이 그대로 두라는 지시만 받음) | 모델이 번역 대상에서 빼고, 그 글은 원본 그대로 남음 |
| 필요한 것 | `docling` 컨테이너 (없으면 힌트 없이 조판 규칙만으로 묶음) | — |

**스캔 쪽**(텍스트 층이 없는 쪽)은 두 방식 모두 **번역하지 않고 원본 그대로** 둡니다. OCR은 쓰지 않습니다 (Docling도 레이아웃 분석만 하고 OCR은 끔).

원본 쪽을 버리고 다시 조판하지 않습니다. 선·표 테두리·음영·로고·그림·벡터 도표는 원본 그대로 남고, **번역한 글만** 지우고 번역문을 같은 자리에 넣습니다.
번역문이 길거나 짧으면 주변의 빈 공간만큼 늘리고, 줄이고, 아래 글을 당기거나 밀어 맞춥니다 (두 방식 모두 같은 조판).

## 실행

```bash
cp .env.example .env            # 번역 LLM 키, POSTGRES_PASSWORD, PDFT_PUBLIC_URL, PDFT_ADMIN_EMAILS 입력
# Google OAuth 클라이언트 JSON을 ./pdft_client_secert.json 으로 저장 (아래 "로그인과 회원")
docker compose up --build
# → http://localhost:9000  (PDFT_PORT로 바꾼 경우 그 포트)
```

`pdft`와 함께 **`docling` 컨테이너**(기본 번역의 레이아웃 분석, CPU 전용)와 **`db` 컨테이너**(회원·로그인 세션, PostgreSQL)가 올라옵니다. 아래 "Docling (CPU 컨테이너)"와 "로그인과 회원" 참고.

`.env` 예: `OPENAI_API_KEY=...`, `META_API_KEY=...` (쓰는 번역 LLM의 키만 필요합니다). 키를 넣은 뒤 `docker compose up -d`로 다시 올리세요. 예제 `models.json`에는 OpenAI GPT-5 mini / GPT-5 nano / GPT-4.1 mini가 들어 있습니다.
처음 실행하면 `config/models.json`이 예제로 자동 생성됩니다. 컨테이너에는 Noto Sans/Serif KR·JP·SC(가변), Nanum, Liberation, DejaVu 폰트가 들어 있습니다.

| 볼륨 | 용도 |
|---|---|
| `./config` | `models.json` (번역 LLM 엔트리포인트·키·모델명) |
| `./data` | 업로드한 PDF, Docling 분석 결과, 번역 결과, 내부 컨텍스트 |
| `./fonts` | 추가 폰트(.ttf/.otf)를 넣고 컨테이너 재시작 |
| `pg-data` (도커 볼륨) | 회원과 로그인 세션 (PostgreSQL) |
| `./pdft_client_secert.json` | Google OAuth 클라이언트 (읽기 전용으로 마운트, 이미지·저장소에 넣지 않음) |

> 포트는 모든 인터페이스(`0.0.0.0`)에 열리며 번호는 `.env`의 `PDFT_PORT`(기본 9000)로 정합니다. API는 Google 계정으로 로그인한 회원만 쓸 수 있습니다. 로그인한 회원은 누구나 서버의 API 키로 번역할 수 있으니, 필요하면 `PDFT_ALLOWED_EMAILS` / `PDFT_ALLOWED_DOMAINS`로 로그인할 수 있는 계정을 제한하세요.

## 로그인과 회원

Google 계정으로 로그인합니다 (OpenID Connect, 인증 코드 + PKCE). 처음 로그인하면 회원이 만들어지고, **문서는 올린 회원의 작업 공간에만** 나옵니다 (다른 회원의 문서 ID로 요청하면 404). 관리자는 대시보드에서 모든 회원의 문서를 **읽기 전용으로** 검토할 수 있습니다. 회원과 세션은 `db` 컨테이너(PostgreSQL)에, 문서는 지금처럼 `./data`에 저장합니다.

**준비 (한 번)**

1. Google Cloud Console → API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트 ID(**웹 애플리케이션**)를 만들고 JSON을 내려받아 프로젝트 루트에 `pdft_client_secert.json`으로 둡니다 (다른 위치면 `.env`의 `PDFT_GOOGLE_CLIENT_JSON`). 이 파일은 `.gitignore`·`.dockerignore`에 들어 있습니다.
2. 그 클라이언트의 **승인된 리디렉션 URI**에 `<PDFT_PUBLIC_URL>/auth/callback`을 등록합니다. 예: `https://pdft.org/auth/callback` (로컬에서도 쓰려면 `http://localhost:9000/auth/callback`도). 등록하지 않으면 Google이 `redirect_uri_mismatch`로 거절합니다.
3. OAuth 동의 화면이 "테스트" 상태면 등록한 테스트 사용자만 로그인할 수 있습니다. 누구나 쓰게 하려면 "프로덕션"으로 게시하세요 (요청 범위는 `openid email profile`뿐이라 Google 검수 대상이 아닙니다).
4. `.env`:

| 키 | 뜻 |
|---|---|
| `PDFT_PUBLIC_URL` | 사람들이 접속하는 주소 (예: `https://pdft.org`). 비우면 요청의 Host / X-Forwarded-Proto에서 정합니다 |
| `POSTGRES_PASSWORD` | 회원 DB 암호 (필수, 아무 긴 문자열). 처음 올릴 때의 값으로 DB가 만들어지므로 나중에 바꾸려면 DB 안에서도 바꿔야 합니다 |
| `PDFT_ADMIN_EMAILS` | 관리자의 Google 계정 이메일 (쉼표 구분). **관리자는 이 목록으로만 정해집니다** (DB에 저장하지 않고 화면에서 지정할 수도 없음). 바꾼 뒤에는 `docker compose up -d`로 다시 올리세요 |
| `PDFT_ALLOWED_EMAILS`, `PDFT_ALLOWED_DOMAINS` | 로그인을 허용할 계정·도메인 (둘 다 비우면 누구나) |
| `PDFT_SESSION_DAYS` | 마지막 사용 후 세션이 끝나는 날 수 (기본 30) |
| `PDFT_AUTH` | `google`(기본) / `off`. `off`는 로그인 없이 모두가 같은 로컬 사용자인 방식으로, 혼자 쓰는 설치에서만 쓰세요 |

**회원 정보** — `users` 표에 Google 계정 ID(`sub`), 이메일, 이름, 프로필 사진 주소, 상태(`active`/`blocked`), 가입·최근 로그인 시각을 둡니다. 로그인할 때마다 이름·이메일·사진을 Google의 값으로 새로 맞춥니다. Google의 토큰은 저장하지 않습니다.

**세션** — 로그인하면 임의의 값이 든 쿠키(`pdft_session`: HttpOnly, SameSite=Lax, https에서는 Secure)를 주고 DB에는 그 해시만 둡니다. 로그아웃하거나 차단되면 바로 끝납니다.

**회원이 할 수 있는 것** — 작업 공간 오른쪽 위 계정 메뉴에서 **로그아웃**, **회원 탈퇴**(계정·세션·올린 문서가 모두 지워짐).

**활동 기록** — `events` 표에 회원이 한 일(로그인, 문서 올림, 번역 시작·끝, PDF 저장, 번역 지움, 문서 삭제)을 시각·문서 이름·세부 내용(방식, 언어, 쪽 수, 누적 토큰)과 함께 남깁니다. 회원이 탈퇴하거나 삭제되면 그 회원의 기록도 함께 지워집니다.

**관리자 대시보드** (`/#/admin`) — `PDFT_ADMIN_EMAILS`에 있는 계정으로 로그인했을 때만 홈과 작업 공간 위쪽에 **대시보드** 버튼이 보이고, 서버도 그 계정에만 응답합니다 (다른 회원은 403).

* **요약**: 회원 수, 문서 수, LLM 요청 수, 입력·출력 토큰 합계.
* **문서**: 모든 회원의 문서 (회원·파일 이름으로 거르기). 줄마다 주인, 상태, 번역 진행, 방식·언어, 올린 때·마지막 작업 시각, 요청 수와 토큰.
* **활동 기록**: 최근 활동 200건 (회원별로 거르기).
* **회원**: 가입일·최근 로그인·문서 수·토큰 사용량, **작업 보기**, **차단 / 해제**, **삭제**(그 회원의 문서와 기록도 삭제). 관리자 계정은 여기서 차단·삭제할 수 없습니다.
* **문서 검토** (문서 줄을 누름): 문서 정보(상태, 방식, 모델, 언어, 토큰, 조판 결과, 오류)와 쪽 목록. 쪽마다 **번역본 / 원본 / 분석**(원본 위에 글상자·남긴 글·Docling 구역)을 바꿔 보고, 오른쪽에서 글상자별 **원문과 번역문**, 번역하지 못한 항목과 이유를 봅니다. 글에 마우스를 올리면 쪽 위의 자리가 표시됩니다. 번역본 PDF도 내려받을 수 있습니다.

관리자는 다른 회원의 문서를 **볼 수만** 있고 번역·수정·삭제는 할 수 없습니다(회원을 삭제하면 문서도 삭제됨). 검토할 때마다 서버 로그에 누가 어느 문서를 열었는지 남습니다. 서버 설정(`PUT /api/settings`, 모델 다시 읽기)도 관리자만 합니다. 회원 기능이 생기기 전에 만든 문서(주인 없음)는 관리자의 작업 공간에 나옵니다.

**DB 관리**

```bash
docker compose exec db psql -U pdft pdft -c "select email, status, created_at, last_login_at from users order by created_at"
docker compose exec db pg_dump -U pdft pdft > pdft-members.sql      # 백업
```

스키마는 앱이 시작할 때 번호 붙은 마이그레이션(`backend/app/db.py`)으로 맞춥니다.

## 사용법

화면은 PDFT를 소개하는 **홈**(`/`)과 **작업 공간**(`/#/work`), **관리자 대시보드**(`/#/admin`)입니다. 따로 가입하는 화면은 없고, 홈의 **Google 계정으로 시작하기**를 누르면 Google 로그인 뒤 **내 문서**(`/#/docs`)가 열립니다.

1. **내 문서**에서 문서를 고르거나 추가합니다. 문서는 카드로 나오고(쪽 수, 상태, 올린 날, 번역 중이면 진행), 카드를 누르면 그 문서의 작업 공간(`/#/work/<문서 번호>`)이 열립니다. 체크박스로 여러 개를 골라 **선택 삭제**하거나 카드의 ✕로 하나씩 지울 수 있고, 파일 이름으로 검색할 수 있습니다. **PDF 추가**(또는 끌어다 놓기)는 여러 파일을 한꺼번에 올릴 수 있고, 한 개만 올리면 바로 그 문서의 작업 공간으로 들어갑니다. 올릴 때 문서를 훑어 번역할 수 있는 쪽을 가려 둡니다 (모델 호출 없음, 비용 없음). 작업 공간 왼쪽 위의 **내 문서** 버튼으로 돌아옵니다. 번역은 작업 공간을 나가도 서버에서 계속되며 목록에 진행이 보입니다.
2. 위쪽 막대에서 **번역 언어**와 **번역 방식**(기본 번역 / 고급 번역)을 고르고 **번역 시작**. 사용자가 고르는 것은 이 둘뿐입니다. 끝난 쪽부터 화면에 반영되고, **중지** 후 **이어서 번역**할 수 있습니다.
   * 진행 상황은 파일 이름 아래 한 줄(하는 일 · 끝난 쪽 수 · %)과 막대 아래의 진행선, 왼쪽 썸네일의 표시(✓ 번역됨 · … 일부 · **원본** 번역하지 않는 스캔·표지 쪽)로 보여 줍니다. 토큰 수, 컨텍스트 게이지, Docling 상태 같은 세부 정보는 화면에 나오지 않습니다.
   * 기본 번역은 먼저 선택한 쪽을 Docling으로 분석하고(쪽마다 한 번, `parse.json`에 저장해 다시 쓰지 않음), 글상자의 글을 묶음으로 보냅니다. Docling 서비스가 꺼져 있으면 레이아웃 힌트 없이 조판 규칙만으로 묶어 계속합니다.
   * 고급 번역은 쪽마다 스크린샷과 지침을 보냅니다.
   * 쪽마다 번역한 방식이 기록되므로, 일부 쪽은 기본으로·일부 쪽은 고급으로 번역할 수 있습니다 (다른 방식으로 다시 하려면 그 쪽의 **번역을 지운** 뒤 번역).
3. 글을 **누르면** 바로 위에 서식 패널이 뜹니다: **글꼴 · 굵기 · 크기 · 색** (이 네 가지만). 바꾸면 그 쪽만 다시 조판됩니다.
4. **PDF 저장**으로 내보냅니다 (번역된 쪽이 하나라도 있어야 켜집니다).
5. **⋯ 메뉴**: PDF 추가 · 선택한 쪽만 저장 · 번역 지우기 · 문서 삭제.

**쪽 선택 (왼쪽 목록)** — 문서를 열면 왼쪽에 쪽 썸네일 목록이 나옵니다.
* 썸네일 왼쪽 위 체크박스로 쪽을 고르고, **Shift+클릭**으로 범위, **Ctrl/⌘+클릭**으로 개별 토글, **전체 선택** 체크박스를 씁니다. 썸네일을 누르면 그 쪽으로 이동합니다.
* **선택한 쪽만 작업합니다**: 번역 시작/이어서 번역은 선택한 쪽의 글만 번역하고, **번역 지우기**는 선택한 쪽의 번역과 서식 변경만 지워 원본 상태로 되돌리며(전체 선택일 때만 내부 컨텍스트도 초기화; Docling 분석 결과는 남겨 두고 다시 씁니다), **선택한 쪽만 저장**은 선택한 쪽만 새 PDF로 저장합니다. 선택하지 않은 쪽은 원본 그대로 남습니다.
* 선택은 문서별로 저장되고, 번역 중에는 바꿀 수 없습니다. 선택이 없으면 번역 버튼이 비활성화됩니다.

**여러 사람이 함께 쓸 때** — 문서는 올린 회원의 것이고 "이어서 작업하기" 목록도 서버가 그 회원의 문서만 돌려줍니다 (다른 기기에서 로그인해도 같은 목록). 번역 언어와 번역 방식은 각자의 브라우저에 저장됩니다(localStorage). 번역에 쓰는 모델과 동시 요청 수는 서버 설정을 따릅니다.

**운영자 설정** — 화면에서 뺀 항목은 서버 설정으로만 바꿉니다. `data/settings.json`을 고치고 다시 시작하거나, 실행 중에 관리자 세션으로 `PUT /api/settings`를 부릅니다 (관리자로 로그인한 브라우저의 개발자 콘솔에서 `fetch("/api/settings", {method: "PUT", headers: {"Content-Type": "application/json"}, body: JSON.stringify({concurrency: 8})})`).

| 키 | 뜻 | 기본값 |
|---|---|---|
| `model_id` | 번역에 쓸 모델 (`models.json`의 `id`). 없으면 첫 모델 | 첫 모델 |
| `concurrency` | 동시에 번역할 쪽 수 (1~16) | 4 |
| `image_long_side` | 고급 번역 스크린샷의 긴 변 px (800~4000) | 2000 |
| `layout_mode` | `place` 제자리 / `flow` 흐름 배치 | `place` |
| `default_font` | 번역문 기본 글꼴 | 첫 글꼴 |
| `auto_compress` | 맥락 요약 자동 갱신 | `true` |


## 기본 번역: Docling 레이아웃 힌트

```
PDF ──► 텍스트 층 (글자 + 굵게/링크 + 정확한 좌표)
    ──► Docling 레이아웃 분석 (구역: 문단·제목·목록·표·그림 …)      선택한 쪽만, 한 번만 (parse.json)
    ──► 글상자(frame) 구성            "이 줄이 앞 줄의 줄바꿈 연속인가"만 판정 + Docling 구역 힌트
    ──► 번역 (글상자의 글을 묶어서)   <t id="N" type="…">원문</t> → 같은 id의 번역문. 맥락 요약·용어집 누적
    ──► 원본 쪽에 얹기 (MuPDF)        글자만 삭제(그래픽 유지) → 같은 자리에 번역문 (아래 "고급 번역"과 같은 조판)
```

**글상자(frame)** = 원본 쪽에 한 덩어리로 인쇄된 글 (줄바꿈으로 이어지는 문단, 제목, 목차의 제목 한 줄, 표 셀 하나 …). 정하는 순서는 이렇습니다 (`frames/basic.py`):

1. **Docling 구역이 먼저, 무조건**: 중심이 같은 Docling 구역 안에 있는 텍스트 층의 줄·조각은 조판 규칙과 상관없이 **모두 한 글상자**입니다. 한 줄에서 빈칸으로 떨어진 두 텍스트박스(`2.1` … `Glossary of terms`), 크기·들여쓰기가 다른 줄, 라벨과 그 뒤 글, 글머리표 항목들도 같은 구역이면 합칩니다. 같은 줄의 조각은 한 줄로 이어 붙이고(글자를 지울 때는 조각마다 지워 그 사이에 있는 글은 건드리지 않음), 둘째 줄 이후의 글머리표는 글 앞에 그대로 둡니다. 구역이 겹치면 가장 작은 구역이 이깁니다.
2. **표는 인식하지 않습니다**: 표 구조 인식은 꺼져 있고, Docling이 표 영역이라고 한 곳과 그 안의 줄 단위 항목, 그림·머리글·바닥글 구역은 힌트로 쓰지 않습니다.
3. **구역이 없는 줄**(Docling이 꺼져 있을 때, 표 안, 어느 구역에도 들지 않은 줄)만 조판 규칙으로 묶습니다:
   * 아래 줄이 바로 밑에 있고, 크기가 비슷하고, 왼쪽/오른쪽/가운데 선을 공유한다 (첫 줄 들여쓰기·글머리표 내어쓰기 허용)
   * **줄바꿈 규칙**: 줄이 바뀌는 이유는 다음 낱말이 안 들어가서이므로, 윗줄이 글상자의 오른쪽 끝까지 차 있어야 한다
   * 글머리표·"1."·콜론으로 끝나는 라벨·굵게↔보통 변화는 새 글상자
   * 한 줄 안에서 멀리 떨어진 조각(목차의 제목과 쪽번호)은 별개의 글상자

Docling 구역이나 규칙 판정이 틀려도 글이 인쇄된 자리는 그대로여서 **줄바꿈이 조금 어색해질 뿐 구조는 깨지지 않습니다.** 읽는 순서는 XY-cut(단 → 띠)으로 정합니다.

* 글자·숫자만 있는 글상자(쪽번호, 숫자 칸)는 보내지 않고 그대로 둡니다. 문단 안의 수식·번호는 글상자와 함께 가며, 모델은 "숫자·수식·코드는 바꾸지 말라"는 지시를 받습니다 (고급 번역은 이것을 아예 빼고 보냅니다).
* **머리글·바닥글**: 문서 절반 이상의 쪽에서 위·아래 같은 자리에 반복되는 글(숫자는 무시)은 머리글·바닥글로 표시해 제자리에서만 맞춥니다. 같은 문구는 한 번 번역한 것을 다시 씁니다(200자 이하 같은 글은 모두).
* 그림 위에 인쇄된 글은 번역하지 않고 그대로 둡니다 ("제외된 글"로 표시).
* 모델이 어떤 글상자의 번역문을 돌려주지 않으면 빠진 것만 다시 묻고(최대 3회), 끝내 없으면 원문 그대로 둡니다 (쪽 정보의 `lost`에 기록).
* **Docling이 꺼져 있으면**: 힌트 없이 조판 규칙만으로 글상자를 묶어 번역합니다 (상태 API의 `progress.notice`에 기록, 화면에는 표시하지 않음).

## 고급 번역: 쪽 스크린샷 (비전 LLM)

```
쪽 스크린샷 + 지침 ──► 비전 LLM ──► {원문, 번역문} 항목들 (JSON)      번역할 글만, 문단·제목·캡션·레이블 단위로
                                      │
PDF 텍스트 층 (글자 + 굵게/링크 + 좌표) ◄┘  원문 ↔ 텍스트 층 대조 (일치율 ≥ 90%)   → 글이 인쇄된 줄들 = 글상자(frame)
                                      ──► 원본 쪽에 얹기 (MuPDF)           글자만 삭제(그래픽 유지) → 같은 자리에 번역문 (설정에 따라 흐름 배치)
```

쪽 하나를 번역하는 요청은 **스크린샷 한 장 + 지침**이고, 모델은 번역할 가치가 있는 글만 `{"lines": […], "translation": …}` 항목으로 돌려줍니다 (수식·숫자·기호·코드·숫자만 있는 표 칸·쪽번호는 제외).
**원문(`lines`: 인쇄된 줄마다 문자열 하나)은 번역에 쓰지 않고 위치를 찾는 데만 씁니다**: PDF의 텍스트 층과 대조해 가장 일치하는 글자들을 찾고(공백·대소문자·합자·따옴표/대시 차이, 오탈자 무시), 일치율이 임계값(기본 90%, 환경 변수 `PDFT_MATCH_THRESHOLD`) 이상이면 그 글자들의 줄이 한 **글상자**가 됩니다. 모델이 `original` 한 줄만 주는 옛 형식도 읽습니다(줄바꿈 정보가 없을 뿐입니다).
글상자의 글꼴 크기·색·굵기·정렬·줄 간격은 그 줄들에서 PDF 그대로 읽어 오고, 번역문은 모델이 준 것입니다. 이후 조판(아래)은 글상자만 보므로 번역문 길이에 따른 크기 조절·배치는 방식이 바뀌어도 같습니다.

* **일치율**: `2 × 일치한 글자 / (원문 길이 + 찾은 구간 길이)`. 같은 문장이 두 번 나오면 아직 안 쓴 쪽을 고르고, `A / B / C`처럼 이어 붙인 레이블은 조각마다 찾아 **조각별 글상자**로 만듭니다 (그림의 레이블이 각자 자리에 번역됨). 줄은 일치한 글자가 40% 이상일 때만 넣어 다른 단의 글이 섞이지 않게 합니다.
* **항목은 시각적 덩어리로 나뉩니다** (지침 `translate/prompts.py`): 한 줄 안에서 넓은 빈칸(탭·열 정렬)으로 떨어진 글은 서로 다른 항목이고, 목록·목차·그림 목록의 줄머리 번호/라벨(`Figure 1.`, `2.1`, `(a)`, `•`)은 `label` 항목, 뒤따르는 글은 `list_item`(그림·표 목록이면 `caption`)으로 따로 냅니다. 내어쓰기로 이어지는 줄은 뒤따르는 글 항목의 `lines`에 함께 들어갑니다. 숫자만 있는 조각(`2.1`)은 번역할 글이 없어 "무시"되고 그 자리는 원본 그대로 남습니다. 어떻게 나눌지는 모델이 정하고, 매칭은 모델이 나눈 대로 따릅니다.
* **글자와 위치를 함께 정렬합니다** (`match/matcher.py`의 `align_item`): 항목의 글자마다 쪽에서 그 글자일 수 있는 자리를 k-gram 앵커로 모으고, 동적 계획법으로 글자마다 자리 하나를 골라 **한 경로**를 만듭니다. 글자에서 다음 글자로 가는 걸음마다 쪽 위의 위치로 점수를 매깁니다(거리는 글자 높이 기준, 방향 있음).
  * 같은 줄에서 바로 오른쪽으로 이어지면 가산, **모델이 줄바꿈이라고 한 자리**에서 아래 줄의 첫머리로 내려가면 가산(줄의 끝 → 줄의 첫머리일수록 더 높음), 모델이 줄바꿈이라고 했는데 같은 줄로 이어지면 감점.
  * 이웃 칸으로 건너뛰기·위로 거슬러 오르기·다른 단으로 가기는 큰 감점(**점프**). 알려 주지 않은 점프는 최종 점수에서 0.15를 깎아 완벽한 글도 90% 아래로 떨어뜨립니다. 모델이 줄바꿈이라 한 자리의 점프(문단이 다음 단으로 이어짐)는 0.03만 깎고, 그 문단은 **단마다 글상자 하나로 나뉘며 번역문은 길이에 비례해 나눠 들어갑니다.**
  * 줄바꿈 정보는 **힌트일 뿐**입니다. 모델이 줄을 합치거나 잘못 끊어도 글이 같으면 같은 자리를 찾습니다(점수 차이가 작아 동점일 때만 영향).
  * 텍스트 층의 저장 순서에 기대지 않으므로, 표를 행 단위로 저장하거나 단 순서가 뒤섞인 PDF도 됩니다 (예: 표의 `Affine / Transformation` 칸에 오른쪽 칸 문장의 `transformation`이 걸리는 경우: 두 후보 중 바로 아래 줄에서 시작하는 왼쪽 칸이 줄바꿈 가산을 받고, 오른쪽 칸은 점프라 탈락).
  * 항목은 **긴 것부터** 찾고, 찾은 글자는 **빼서** 다음 항목이 다시 가져가지 못하게 합니다 (못 찾은 항목은 다른 항목이 빠진 뒤 다시 시도, 최대 3회). 거부된 항목은 억지로 붙이지 않고 "못 찾은 항목"으로 보고되며 그 글은 원본 그대로 남습니다.
* **못 찾은 항목**(일치율 미달, 환각된 문장 등)은 글상자가 되지 않고 그 글은 원본 그대로 남습니다. 쪽 번역이 끝나면 상태 API의 `progress.warnings`에 쪽 수가 기록되고, `GET /api/jobs/<id>/pages/<n>/layout`의 `lost`에서 항목을 볼 수 있습니다.
* **응답이 잘리면** (긴 쪽) 마지막 항목 다음부터 이어서 요청하고, **읽을 수 없는 답**은 같은 쪽을 다시 요청합니다 (한 쪽당 최대 4회). 그래도 안 되면 그 쪽은 번역되지 않은 채 남아 **이어서 번역**으로 다시 시도할 수 있습니다. 키·모델 오류(401, 이미지 미지원 등)는 작업을 멈추고 오류로 표시하며, 끝낸 쪽은 유지합니다.
* **맥락**: 쪽마다 짧은 배경 요약과 용어집(그 쪽에 나오는 용어만)이 지침에 붙습니다. 번역된 쌍을 모아 요약·용어집을 갱신하는 것은 텍스트 호출이고, 모델이 쪽마다 알려 준 `terms`가 용어집에 쌓입니다.
* **원본 쪽 유지**: 번역한 글의 글자만 지우고(이미지·선 그래픽은 유지) 그 자리에 번역문을 넣습니다. 링크 밑줄 선도 같이 지웁니다. 번역하지 않는 글(모델이 뺀 수식·숫자·URL·코드)은 그대로 남습니다.
* **번역문 배치** (설정 → 조판 → 번역문 배치):
  * **제자리**(기본): 모든 번역문이 원본 글이 있던 자리에 머뭅니다. ① 원래 상자 ② 옆 빈 공간으로 넓히기(한 줄 글) / 아래 빈 공간으로 늘리기(다음 글·선·그림·남긴 글 앞까지) ③ 그래도 안 되면 글자 크기를 55%까지 줄이기. 번역문이 짧으면 그 아래에 빈틈이 남지만, 번호·수식·그림 참조처럼 남긴 글과 어긋나지 않고 원본과 같은 높이에서 대조할 수 있습니다.
  빈 공간은 기하로만 판단합니다 — 다른 글, 선, 상자, 그림이 인쇄된 곳은 막히고, 표 셀·음영 상자·그림 안의 글은 그 안에서만 움직입니다. 번역하지 않고 남은 글도 "고정된 것"으로 취급합니다.
  * **흐름 배치**: 옆에 다른 글이 없고 상자 안이 아닌 글은 위에서 아래로 쌓아, 번역문이 짧아져 생긴 빈틈은 아래 글을 당겨 메우고 길어지면 밀어 냅니다(원본의 글 사이 간격 유지). 선·그림·번역하지 않는 글에 닿으면 거기서 멈춥니다. 번역하지 않고 남긴 글이 같은 줄에 있는 글상자(예: 첫 줄 앞에 원본 번호 `6.`가 남은 문단)는 그 글과 어긋나지 않도록 **제자리에 고정**되고, 흐름은 그 위아래에서 끊깁니다. 번역문이 원문보다 훨씬 긴 언어(글자 크기를 줄이기 싫을 때)에 맞습니다.
* **머리글·바닥글**: 모델이 `header`/`footer`로 표시한 글은 제자리에서만 맞춥니다 (흐름 배치 없음). 쪽마다 따로 번역되므로 같은 문구가 쪽마다 조금 다르게 번역될 수 있습니다. 쪽번호는 보통 모델이 제외해 원본 번호 그대로 남습니다.
* **표지·전면 이미지 쪽**은 원본 쪽을 그대로 가져옵니다 (쪽 전체가 그림 한 장이고 글자가 30단어 미만인 쪽, 글자 있는 문서에 한함). 전면 이미지 위에 보이지 않는 OCR 글자만 얹힌 쪽은 번역문이 들어갈 자리를 주변 색으로 칠해 원본 글을 가립니다.
* **정렬**: 모델이 항목마다 `align`(left/center/right, 양쪽 맞춤은 left)을 답합니다. 한 줄짜리 글은 PDF에 정렬 정보가 없어 이웃 글과의 끝선 일치로만 짐작할 수 있는데 우연히 오판하기 쉬우므로 **모델 답을 우선**합니다. 여러 줄 문단은 줄 끝선이 실제로 가지런하면 그 측정값을 따릅니다. 답이 없거나 이상하면 끝선 기반 추정(왼쪽 끝이 다른 글 2개 이상과 같으면 왼쪽)을 씁니다.
* **서식 보존**: 글자 크기·색·굵기는 글상자별로 PDF에서 읽어 옵니다. 굵게(`**`)·기울임은 모델이 화면에서 본 대로 표시하고, 링크는 번역문에 링크 글자가 그대로 남아 있을 때(인쇄된 URL 등)만 복원합니다.
* **스캔 쪽**(텍스트 층이 없는 쪽)은 대조할 글자가 없어 **번역하지 않고 원본 그대로** 둡니다 (열 때 알림으로 표시). PDF 안에 이미 OCR 텍스트 층이 있는 스캔 PDF는 그 층을 씁니다.
* 번역 호출은 `llm/vision.py`의 `chat_with_image()`(스크린샷 한 장), 요약 갱신과 기본 번역의 호출은 문자열 두 개만 받는 `llm/clients.chat()`(텍스트 전용)입니다.

## Docling (CPU 컨테이너)

기본 번역의 레이아웃 분석은 **Docling**이 맡습니다 (OCR은 끈 채로, 구역만 찾음). 무료이고 문서가 외부로 나가지 않습니다.

Docling은 `docker-compose.yml`의 별도 컨테이너(`docling`, 소스는 `docling/`)로 돌며 **GPU 없이 CPU만** 씁니다 (CPU 전용 PyTorch). 앱 컨테이너가 compose 네트워크 안에서 `http://docling:8765`로 부르고, 이 포트는 호스트에 열지 않습니다.

```bash
docker compose up -d --build   # pdft + docling 함께 올립니다
```

* 모델 가중치는 처음 분석할 때 내려받아 `docling-models` 볼륨에 저장됩니다 (이후엔 재사용).
* 번역할 쪽만 잘라 보내고, 결과는 작업 폴더의 `parse.json`에 쪽별로 쌓아 다시 쓰지 않습니다. CPU에서는 쪽당 몇 초가 걸립니다 (처음엔 모델 내려받기 시간이 더해짐).
* CPU 코어를 모두 쓰며, 줄이려면 `.env`에 `DOCLING_THREADS=4`처럼 적습니다. 분석은 한 번에 한 문서씩 처리합니다.
* **표 구조 인식은 끄고 씁니다** (번역에는 필요 없고 느림). 끄면 Docling은 표 안 글을 줄 단위 항목으로 줍니다. 이 항목은 구역 힌트로 쓰지 않습니다 (줄마다 끊기는 것을 막기 위해).
* 환경 변수: `PDFT_DOCLING_URL`(기본 `http://docling:8765`), `PDFT_DOCLING_TOKEN`(선택, 두 컨테이너에 같은 값을 주면 인증을 요구), `DOCLING_THREADS`.

## 번역 LLM 설정: models.json

```json
{
  "models": [
    {
      "id": "openai-gpt-4.1-mini",          // 고유 id
      "name": "OpenAI · GPT-4.1 mini",      // 모델 이름 (표시용)
      "type": "openai",                     // openai | anthropic | gemini
      "endpoint": "https://api.openai.com/v1",
      "api_key": "${OPENAI_API_KEY}",       // 직접 입력하거나 ${환경변수}
      "model": "gpt-4.1-mini",
      "context_window": null,               // (선택) 컨텍스트 한도를 직접 지정
      "max_output_tokens": 8192,            // (선택) anthropic/gemini 출력 상한
      "params": { "temperature": 0.2 },     // (선택) 요청 본문/generationConfig에 그대로 병합
      "prompt_cache_key": null,             // (선택) true면 작업별 prompt_cache_key 전송 (api.meta.ai / api.openai.com은 자동)
      "headers": {}                         // (선택) 추가 헤더
    }
  ]
}
```

* `type: "openai"`는 `/chat/completions` 호환 서버 전부(OpenAI, Meta AI, OpenRouter, Together, Groq, DeepSeek, vLLM, LM Studio, Ollama 등)에 쓸 수 있습니다. 실제 JSON에는 주석을 쓸 수 없습니다(위 `//`는 설명용).
  수정 후 **모델 → models.json 다시 읽기**로 재시작 없이 반영됩니다. API 키는 서버 밖으로 나가지 않습니다.
* **컨텍스트 한도 조회** 순서: `models.json`의 `context_window` → 제공자 API(Anthropic `max_input_tokens`, Gemini `inputTokenLimit`, OpenAI 호환 `/models`의 `context_length`, Ollama `/api/show`) → 모델명 내장 표(추정) → 8,192.
  Meta AI처럼 한도를 알려주지 않는 곳은 `context_window`를 직접 지정하세요.
* **맥락 요약 + 용어사전 (요청마다 보내는 맥락은 이 둘뿐)**: 번역 요청에는 시스템 지시문, **짧은 맥락 요약**(영어, 기본 최대 700토큰), 이번 묶음에 **실제로 나온 용어집 항목**(최대 1,500토큰), 그리고 번역할 글만 들어갑니다. 이전에 번역한 원문·번역문 쌍은 보내지 않습니다.
  새 번역 쌍은 내부에 모아 두었다가 6,000토큰이 쌓이면(`PDFT_SUMMARY_EVERY`) **요약 갱신 호출 1회**로 요약과 용어집에 반영하고 비웁니다. 이 호출은 번역과 나란히 돌기 때문에 번역이 멈추지 않으며, 진행 중인 쪽은 시작할 때의 요약·용어집 사본을 그대로 씁니다. 갱신에 실패하면 쌍은 그대로 남아 몇 쪽 뒤에 다시 시도합니다.
  용어집은 번역 응답에 딸려 오는 `<term>`으로 쌓이고(처음 정해진 번역 우선), 요약 갱신 때도 추가됩니다. 요청 크기는 문서가 길어져도 늘지 않습니다(288쪽 실측 이전 방식: 요청당 약 10만 토큰 → 이제 지시문 약 0.6천 + 요약 + 용어집 + 글).
  설정 `auto_compress`를 끄면 요약은 `POST /api/jobs/<id>/compress`로만 바뀝니다. 상태 API의 `gauge`는 **요청마다 보내는 맥락(지시문+요약+용어집)**과 요약 대기량을 돌려줍니다 (화면에는 표시하지 않음). 이전 방식으로 쌓인 작업의 이력은 처음 요약할 때 최근 16,000토큰만 읽고 정리됩니다.
  **프롬프트 캐시**: 요청 앞부분(시스템 프롬프트·요약)은 요약이 바뀌기 전까지 같고, 요청마다 달라지는 용어집과 이번 글은 맨 뒤에 둡니다. api.meta.ai와 api.openai.com에는 `prompt_cache_key`(작업별 고정값)를 자동으로 보냅니다. 다른 OpenAI 호환 서버는 `models.json`에 `"prompt_cache_key": true`로 켤 수 있습니다. 상태 API의 `usage`에 작업별 **누적 LLM 입력/출력 토큰, 요청 수, 캐시된 입력**이 들어 있습니다 (화면에는 표시하지 않음).
  이 내용은 `data/jobs/<id>/internal/`에만 저장되며 어떤 API 응답에도 없습니다 (API에는 토큰 수치만 나옴). 조정: `PDFT_SUMMARY_EVERY` · `PDFT_SUMMARY_TOKENS` · `PDFT_GLOSSARY_TOKENS` · `PDFT_SUMMARY_FEED`.
* **OpenAI**: `type: "openai"` + `https://api.openai.com/v1` + `${OPENAI_API_KEY}`. GPT-5 계열처럼 `temperature`(기본값만 허용)나 `reasoning_effort`를 받지 않는 모델이 있어서, **서버가 400으로 거절한 `params` 항목은 그 모델에서 자동으로 빼고** 요청을 다시 보냅니다(로그에 한 줄 남음). 새 모델은 `model`만 바꿔 항목을 복사해 추가하면 됩니다. GPT-5 계열에는 `"reasoning_effort": "minimal"`로 추론 토큰(출력 비용)을 줄입니다.
* **동시 요청 (설정 `concurrency`)**: 동시에 번역할 쪽 수(1~16, 기본 4)입니다. 각 쪽은 시작할 때의 맥락(요약·용어집) 사본으로 번역하고 끝나면 새 번역 쌍·용어를 공유 맥락에 합칩니다. 한 쪽 안의 요청 묶음도 동시에 보내며, 전체 동시 요청 수는 이 값을 넘지 않습니다.
  429(요청 한도)는 `Retry-After`를 따라 자동 재시도하지만 API가 동시 요청을 제한하면 값을 낮추세요.
  **같은 시점에 번역되는 쪽끼리는 서로의 번역과 새 용어를 보지 못하므로** 용어 일관성이 조금 떨어질 수 있습니다 (1 = 순차, 용어 일관성 최대). 토큰 사용량은 비슷하고, 프롬프트 캐시 적중이 약간 줄 수 있습니다.
* LLM 호출 함수는 문자열 두 개(`system`, `user`)만 받습니다. 페이지 이미지가 전송될 경로가 없습니다.

## 한계

* **개인정보**: 기본 번역은 **글상자의 글**(과 요약·용어집)만, 고급 번역은 **쪽 스크린샷**(과 요약·용어집 텍스트)을 선택한 모델로 전송합니다. Docling 분석은 내 컴퓨터 안의 컨테이너에서 이뤄집니다. 문서를 외부로 보낼 수 없다면 로컬 모델(Ollama 등, 고급 번역은 이미지 입력 지원 모델)을 쓰세요. PDF 읽기·대조·조판은 모두 내 컴퓨터 안에서 이뤄집니다.
* **텍스트 층에 의존합니다**: 위치는 PDF 텍스트 층에서 찾으므로 텍스트 층이 없는 스캔 쪽은 번역되지 않습니다. 문장 중간에 수식이 끼어 글자 모양이 달라지는 경우 일치율이 떨어져 "못 찾은 항목"이 늘 수 있습니다. (텍스트 층의 저장 순서는 상관없습니다. 단이 이어지는 문단은 모델이 줄 정보를 주어야 단마다 글상자로 나뉘어 찾아집니다.)
* **모델 품질에 달려 있습니다**: 원문을 글자 그대로 옮겨 적지 못하면(요약·교정·LaTeX 변환) 일치율이 낮아지고, 번역할 글을 빠뜨리면 그 글은 원본 그대로 남습니다. 지침은 `translate/prompts.py`에 있습니다.
* **기울임**은 반영되지 않습니다 (가변 폰트에 이탤릭 면이 없음 → 일반체). 굵게·링크 색/밑줄은 반영됩니다. 링크는 **클릭 가능한 주석으로는 새로 만들지 않습니다** (원본의 링크 영역은 그대로 남지만 글이 움직이면 어긋날 수 있음).
* 그림 안의 글(스크린샷, 도표 속 글자)은 번역하지 않습니다. 벡터 도표 속 글자도 그림 위에 인쇄된 것이면 원본 그대로입니다.
* 번역문이 매우 길어 아래가 선·그림으로 막힌 곳은 글자가 작아집니다 (최소 55%, 그래도 안 들어가면 더 줄여서 글이 사라지지 않게 합니다). 글은 그려진 높이를 기준으로 아래 글을 밀기 때문에, 선·URL 같은 고정 요소와 겹치지 않도록 자리를 계산합니다. 그래도 안 들어가면 넘치는 개수가 상태 API의 `compose.fit`에 기록됩니다. 번역문 때문에 다음 쪽으로 이어 붙이지는 않습니다 (쪽 구성은 원본과 같음).
* **제자리 배치**에서는 번역문이 짧은 만큼 빈틈이 남고, 길면 아래 빈 공간이 없을 때 글자가 작아집니다 (문단마다 글자 크기가 조금 다를 수 있음). 흐름 배치에서도 **옆에 다른 글이 있는 글**(2단 조판, 표 셀, 그림 설명 옆 글)은 제자리에서 맞추고, 번역하지 않는 글(URL 등)이 글 사이에 끼어 있으면 거기서 흐름이 끊깁니다.
* 회전된 글자(세로쓰기)와 회전된 쪽은 번역하지 않고 그대로 둡니다.
* 이전 버전(Docling·글상자 휴리스틱 방식)으로 만든 작업은 열리지만 그때의 번역은 새 방식과 맞지 않으니, 그 쪽을 **번역 초기화** 후 다시 번역하세요. 분석 단계와 "구조 다시 정리", Docling 서비스는 없어졌습니다.
* 서버는 워커 1개입니다 (번역 작업이 프로세스 내 태스크). API는 로그인한 회원만 쓸 수 있습니다 ("로그인과 회원").

## 검증 내역

NIST FIPS-197(AES) 13쪽(제목·본문·표 레이블·그림 캡션·수식이 섞인 쪽)에 저장해 둔 모델 응답을 넣어 매칭과 조판을 확인했습니다: 항목 10개가 모두 90% 이상 일치했고, 수식·쪽번호는 그대로 남았으며, 그림 레이블은 각자 자리에 번역되고, 긴 번역문은 아래 빈 공간·글자 크기 축소(흐름 배치를 켜면 아래 글 밀기)로 맞춰졌습니다.
자동 테스트(`cd backend && python -m unittest discover -s tests -t .`)는 매처(오탈자·중복 문장·2단·조각 레이블·마크다운 잡음)와 쪽 번역 경로(응답 잘림 이어받기, 읽을 수 없는 답 재시도·포기, 빈 쪽, 환각된 원문, API 오류 시 중단)를 합성 PDF와 스크립트된 모델로 확인합니다.
실제 모델 호출·2단 조판·세로쓰기·회전 쪽·긴 문서는 시험하지 못했습니다. 번역 문구의 정확성은 사용하는 LLM에 달려 있습니다.

## 개발

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r backend/requirements.txt
PDFT_DATA_DIR=./data PDFT_CONFIG_DIR=./config PDFT_FONT_DIRS=./fonts:/path/to/fonts \
PDFT_FRONTEND_DIR=./frontend PDFT_EXAMPLE_MODELS=./config/models.example.json \
  uvicorn app.main:app --app-dir backend --reload --port 9000
```

주요 API: `GET /api/bootstrap`, `POST /api/jobs`(업로드 + 번역 가능한 쪽 가리기), `POST /api/jobs/{id}/translate {model_id, target_lang, concurrency, mode: basic|advanced, ...}`, `GET /api/docling`(Docling 상태), `POST /api/jobs/{id}/cancel|compress|reset`, `PUT /api/jobs/{id}/selection {pages}`(작업 대상 쪽),
`GET /api/jobs/{id}/status`, `GET /api/jobs/{id}/pages/{n}/image|boxes|layout`, `PATCH /api/jobs/{id}/blocks/{frame}`(글꼴/굵기/크기/색), `GET /api/jobs/{id}/export[?selected=true]`.

구조: `match/`(원문↔텍스트 층 대조 `matcher.py`, 모델 JSON 읽기 `llm_json.py`) · `structure/`(텍스트 층 읽기, 읽는 순서 XY-cut) · `parse/`(Docling 클라이언트·변환) · `frames/`(고급 번역 결과→글상자 `build.py`, 기본 번역의 조판 규칙+Docling 힌트 글상자 `basic.py`, 원본 쪽 위 조판 `compose.py`, 쪽 기하 `geometry.py`) · `compose/`(마크업→HTML, 재조판 매니저) · `translate/`(프롬프트·컨텍스트·쪽 단위 파이프라인) · `llm/`(텍스트 `clients.py`, 스크린샷 `vision.py`) · `pdf/`(폰트·렌더) · `auth/`(Google 로그인·세션·회원·활동 기록) · `db.py`(PostgreSQL 연결·마이그레이션) · `tests/`.
